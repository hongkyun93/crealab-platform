발명 제안서 (Invention Disclosure Form)

1. 발명의 명칭 (Title of Invention)

국문: 일정 데이터의 상업적 가치 평가 및 제안 객체 자동 생성 시스템 및 그 방법
영문: System and Method for Evaluating Commercial Value of Schedule Data and Automatically Generating Proposal Objects

2. 발명의 배경 및 목적 (Background & Objectives)

2.1 종래 기술의 문제점 (Problems in Prior Art)

  • 일정 관리와 상업적 제안의 분리: 종래의 인플루언서 마케팅 시스템에서 크리에이터의 '개인 일정(Schedule)'과 브랜드와의 '계약(Contract)'은 별도의 도구에서 관리됨.
  • 기회 손실 (Opportunity Loss): 크리에이터가 여행, 이사, 결혼 등 고가치 상업적 이벤트(High-Value Commercial Event)를 계획하더라도, 이를 브랜드가 적시에 인지하고 제안하기 위한 자동화된 창구가 부재함.
  • 협상 비효율: 브랜드는 크리에이터의 일정을 알 수 없어 무차별적인 제안(Cold DM)을 발송하며, 이는 낮은 성사율로 귀결됨.
  • 협업의 비대칭성 부재: 기존 협업 도구(Google Docs 등)는 모든 사용자에게 동일한 화면과 권한을 부여하여, '협상(Negotiation)'이라는 특수한 비대칭적 상황(갑/을 관계, 가격 비공개 영역 등)을 지원하지 못함.

2.2 본 발명의 목적 (Objective)

  1. [제1발명] 모먼트 엔진: 일정 데이터를 상업적 제안 객체로 자동 변환.
  2. [제2발명] 통합 워크스페이스: 단일 제안 객체에 대해 브랜드와 크리에이터에게 서로 다른 권한과 뷰(View)를 제공하며 실시간 동기화.

3. 발명의 구성 및 특징 (Configuration & Features)

3.1 하드웨어 구성 (Hardware Components - 필수 요소)

본 발명은 단순한 비즈니스 모델이 아닌, 구체적인 하드웨어 장치들의 상호작용으로 구현된다.

  1. 사용자 단말기 (User Terminal): 터치스크린과 통신 모듈을 포함하며, 캘린더 인터페이스를 통해 사용자의 일정 입력을 수신하고, 서버로부터 수신된 제안 객체의 상태(Status)를 시각적으로 렌더링하는 장치.
  2. 중앙 처리 서버 (Central Processing Server): 다수의 사용자 단말기로부터 수신된 일정 데이터를 저장하고, 내장된 '모먼트 엔진(Moment Engine)'을 통해 연산을 수행하는 컴퓨팅 장치.
  3. 데이터베이스 (Database):
    • 이벤트 DB: 원본 일정 데이터(EventID, Date, Title) 저장.
    • 제안 DB: 가공된 상업적 제안 데이터(ProposalID, SlotList, Pricing) 저장.
    • 단가표 DB: 각 사용자별 미디어 단가(RateCard) 저장.

3.3 핵심 알고리즘 설명 (Detailed Description of Algorithm)

[청구항 1] 상업적 슬롯 자동 할당 시스템
프로세서(Processor)를 포함하는 서버 시스템으로서, 상기 프로세서는:
1. 통신 모듈을 통해 제1단말기로부터 일정 데이터 패킷을 수신하고,
2. 상기 일정 데이터의 기간(Duration) 값을 추출하여 메모리에 로드하고,
3. 기설정된 슬롯 생성 규칙(Rule Set)을 적용하여, 상기 기간 값에 비례하는 복수의 광고 슬롯(Ad Slots) 객체를 생성하여 데이터베이스에 저장하는 것을 특징으로 하는 시스템.

[청구항 2] 동적 단가 산정 방법
컴퓨터로 구현되는 방법에 있어서,
1. 사용자의 식별자(User ID)를 키(Key)로 하여 단가표(Rate Card) 데이터를 조회하는 단계;
2. 입력된 일정의 계절적 특성(Seasonality) 데이터를 로드하는 단계;
3. 상기 단가표의 기본값에 상기 계절적 특성에 따른 가중치(Weight)를 곱셈 연산하여 최종 제안 단가를 산출하는 단계;
를 포함하는 상업적 제안 객체 생성 방법.

[제2발명] 비대칭 상태 동기화 워크스페이스 (Asymmetric State Synchronization)

3.4 통합 워크스페이스 아키텍처
- Dual-View, Single-State 구조:
- 데이터베이스에는 하나의 Proposal 객체만 존재함.
- 그러나 서버는 요청자의 Role (Brand vs Creator)에 따라 전혀 다른 JSON 데이터를 내려줌.
- 브랜드 뷰: Outcome (결과물) 위주, Payment (결제) 버튼 활성화.
- 크리에이터 뷰: Task (할일) 위주, Payment 버튼 비활성화, Payout (정산) 정보 표시.

Creadypick 특허 신규성 심층 분석 보고서 (Deep Novelty Analysis)

1. 요약 (Executive Summary)

"모먼트-투-상업화(Moment-to-Commercialization)" 엔진은 기존 시장에 존재하는 솔루션과 명확히 구분되며, 특허 등록 가능성이 매우 높은 "블루오션" 기술로 판단됩니다.

기존 인플루언서 마케팅 플랫폼들은 캘린더를 "일정 관리(Scheduling)" 도구로만 활용하지만, Creadypick은 이를 "재고 생성(Inventory Generation)" 도구로 활용한다는 점에서 기술적 진보성(Inventive Step)이 뚜렷합니다.

2. 기존 기술의 한계 (The "Prior Art" Trap)

A. 단순 포스팅 예약 시스템 (Content Scheduling)

  • 대표 주자: Later, Hootsuite, Sprout Social 등.
  • 특허 동향: "데이터베이스에 저장된 콘텐츠를 특정 시간에 소셜 미디어 API로 전송하는 방법"에 집중됨.
  • 한계: 이미 제작된 콘텐츠를 언제 배포할지만 관리함. 콘텐츠 제작 전 단계의 "계약 체결"과는 무관함.

B. 인플루언서 마켓플레이스 (Influencer Marketplaces)

  • 대표 주자: CreatorIQ, AspireIQ, Grin 등.
  • 특허 동향: "조건에 맞는 인플루언서를 검색하고 매칭하는 알고리즘"에 집중됨.
  • 한계: 매칭이 성사된 후에야 캘린더가 등장함(캠페인 일정 관리용). 즉, 캘린더가 매칭의 결과이지, 매칭의 원인(Source)이 아님.

3. Creadypick의 기술적 차별성 (The "Gap")

구분 기존 방식 (Marketplace) Creadypick 방식 (Moment Engine)
시작점 브랜드의 모집 공고 (Brief) 크리에이터의 개인 일정 (Calendar)
데이터 흐름 공고 -> 지원 -> 매칭 -> 일정 확정 일정 감지 -> 상품화 -> 매칭 -> 계약
기술적 특징 검색 및 필터링 (Search & Filter) 객체 형변환 (Type Transformation)

핵심 주장: "일정(Time)"이라는 비상업적 데이터를 "상품(Asset)"이라는 상업적 데이터로 자동 변환(Auto-Transformation)하는 로직 자체가 새로운 발명입니다.
