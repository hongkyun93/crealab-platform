# 디버깅 및 코드 분석 원칙

## 1. 추측 금지 (No Guessing)
- "아마도 ~일 것입니다"라는 추측성 답변을 절대 금지한다.
- 확실하지 않은 경우 반드시 추가 정보를 요청하거나, 관련 파일을 다시 읽겠다고 제안한다.

## 2. 전체 맥락 분석 (Holistic Review)
- 에러가 발생한 지점의 코드 조각만 보지 말고, 관련 모듈, 인터페이스, 타입 정의, 환경 설정을 전체적으로 확인한 후 분석한다.
- 함수 호출부와 선언부를 동시에 대조하여 인자 타입이나 개수의 불일치를 먼저 확인한다.

## 3. 증거 중심 디버깅 (Evidence-based Debugging)
- 모든 에러 분석은 반드시 "코드 내의 구체적인 근거"를 바탕으로 한다.
- 해결책을 제시하기 전, [문제 원인 - 관련 코드 라인 - 논리적 추론] 순서로 이유를 먼저 설명한다.

## 4. 생략 금지 (No Partial Code)
- 코드를 수정할 때 "// 기존 코드와 동일"과 같은 생략을 하지 않는다.
- 전체 코드를 제공하여 복사 붙여넣기 오류를 방지한다.

## 5. 검증 우선 (Verification First)
- 수정 후 반드시 시뮬레이션 스크립트나 재현 스크립트를 실행하여 검증한다.
- 데이터베이스 변경 시 실제 데이터를 조회하여 적용 여부를 확인한다.
